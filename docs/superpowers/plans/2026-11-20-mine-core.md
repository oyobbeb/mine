# mine 코어(스파이크 + 1단계: 데몬과 세션) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ghostty 안에서 tmux 대신 하루 동안 쓸 수 있는 Rust `mine`을 만든다. 세션은 데몬이 재시작돼도 살아 있어야 한다.

**Architecture:** 바이너리 `mine` 하나에 다음 네 가지 역할이 들어간다.
- 클라이언트(TUI)
- 데몬(`mine daemon`)
- 세션별 보관 프로세스(`mine hold`)
- 훅 수신(`mine _event`)

보관 프로세스가 PTY를 쥐고 출력 2 MiB를 보관한다. 데몬은 보관 프로세스에 붙어 세션마다 `alacritty_terminal` 화면을 유지하고, 클라이언트에 스냅숏과 실시간 출력을 보낸다. 모든 연결은 유닉스 소켓 위의 JSON 줄 프로토콜이다.

**Tech Stack:** Rust 1.94(edition 2024), tokio, ratatui 0.30 + crossterm 0.29(출력 전용), alacritty_terminal 0.26, portable-pty 0.9, clap 4, serde/serde_json, base64, sha2, libc, anyhow. 테스트용으로 tempfile을 쓴다.

**Spec:** `docs/superpowers/specs/2026-11-20-mine-multiplexer-design.md` (설계 5.1–5.3, 5.9, 5.10의 0·1단계)

## 범위

이 계획에 넣는 것:
- 0단계 스파이크
- 1단계: 데몬, 보관 프로세스, claude·codex·shell 세션, 아이콘 줄과 상태별 목록, 훅으로 상태 감지, 다시 붙기, 스크롤·선택 복사·복사 모드
- Python 프로토타입 교체

빼는 것: 한도와 넘기기(2단계), 재부팅 복원(3단계), graph/files 칸(4단계), 원격(5단계), 마스터(6단계), 브라우저(7단계), brew(8단계), `⌃k` 찾기. 2단계부터는 스파이크 결과를 반영해 단계마다 따로 계획한다.

## Global Constraints

- 바이너리는 `mine` 하나다. macOS(Apple Silicon)가 기준이고, Linux에서도 컴파일되게 한다.
- 상태 폴더는 `~/.mine`이다. `MINE_STATE_DIR`가 있으면 그 경로를 쓴다. 새로 만드는 폴더 권한은 `0o700`이다.
- 유닉스 소켓 경로는 macOS 한도인 104바이트를 넘으면 안 된다. 보관 소켓은 `<state>/run/<sha256(id) 앞 12자>.sock`에 둔다. 테스트 상태 폴더는 `/tmp` 아래 짧은 경로(`tempfile::Builder::new().prefix("m").tempdir_in("/tmp")`)에 만든다.
- 접두 키는 `⌃a`(0x01)다. `⌃a ⌃a`를 누르면 0x01 자체가 세션으로 간다.
- 상태 기호와 목록 순서는 `◆ 승인 대기 → ◐ 작업 중 → ✓ 끝남 → ○ 대기`다. 종료된 세션은 끝남 그룹에 넣고 `종료됨`으로 표시한다.
- 계정 칩 색: claude-a(A) `#e5c07b`, claude-b(B) `#c678dd`, codex(C) `#56b6c2`. shell 세션은 칩이 없다.
- claude-a는 `CLAUDE_CONFIG_DIR`을 설정하지 않는다(`~/.claude` 그대로). claude-b는 `CLAUDE_CONFIG_DIR=<state>/profiles/claude-b`다. mine은 자격 증명을 읽거나 저장하지 않는다.
- 보관 출력 버퍼는 2 MiB(`RING_CAP = 2 * 1024 * 1024`), 스크롤백은 10,000줄(`SCROLLBACK = 10_000`)이다.
- 프로토콜 버전은 클라이언트↔데몬 `VERSION = 1`, 데몬↔보관 `HOLD_VERSION = 1`이다. 버전이 다르면 연결을 끊고 오류를 보여 준다.
- 위 Tech Stack에 없는 의존성은 추가하지 않는다. 꼭 필요하면 커밋 본문에 이유를 적는다.
- 커밋 규칙:
  - 제목은 `type(scope): 한글 명령형 요약`, 본문에는 바꾼 것·이유·검증을 적고 마지막 줄에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙인다.
  - 한 태스크가 한 커밋이다.
  - 커밋 전에 `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`가 통과해야 한다. Task 12 전까지는 `python3 -B -m unittest discover -s tests`도 통과해야 한다.
- 버전 관리는 GitButler(`but`)로만 한다. 코드 커밋은 `feat/rust-core` 브랜치에 쌓는다.
  - 첫 커밋: `but commit --above docs/mine-design -b feat/rust-core -F - <ids>`
  - 그다음: `but commit -b feat/rust-core -F - <ids>`
  - `<ids>`는 `but diff`에서 이 태스크가 바꾼 파일 ID만 고른다. 같은 저장소에서 다른 에이전트가 작업할 수 있으니 남의 변경은 넣지 않는다.

## Review Focus

1. **한글·이모지 같은 넓은 문자:** 세션 출력과 세션 이름에 넓은 문자가 섞여도 칸이 밀리지 않아야 한다. → Task 4 `snapshot_rebuilds_same_screen`, Task 9 `term_render_handles_wide_chars`
2. **출력 폭주:** 빌드 로그나 큰 파일을 `cat`해도 메모리가 무한히 늘지 않고 다른 명령이 응답해야 한다. → Task 3 `ring_keeps_last_bytes`, Task 6 `flood_output_keeps_ls_responsive`
3. **창 크기 변경:** Ghostty 창 크기를 바꾸거나 목록을 접으면 세션 프로그램이 새 크기를 받아야 한다. → Task 3 `forwards_input_and_resize`
4. **붙여넣기 안의 0x01:** 붙여넣은 글에 `⌃a` 바이트가 있어도 명령으로 해석하지 않아야 한다. → Task 7 `prefix_inside_paste_passes_through`
5. **남은 소켓 파일:** 데몬이 비정상 종료해 `daemon.sock` 파일만 남아도 다음 실행이 정상이어야 한다. → Task 6 `stale_socket_is_replaced`

  - **Shell:** `[$SHELL 또는 /bin/zsh, "-l"]`
  - **Claude:** `["claude", "--settings", <JSON>]`, 모델이 있으면 `--model <m>`, `resume_id`가 있으면 `--resume <id>`.
    - JSON: `{"hooks":{"UserPromptSubmit":[H],"Stop":[H],"Notification":[{"matcher":"permission_prompt","hooks":[C]}]}}`. 여기서 `H = {"hooks":[C]}`, `C = {"type":"command","command":"<exe> _event <session_dir>"}`이고 명령은 `shlex` 방식으로 따옴표 처리한다.
    - claude-b에만 `CLAUDE_CONFIG_DIR=<state>/profiles/claude-b`를 붙인다.
  - **Codex:** `["codex", "-c", "hooks.UserPromptSubmit=<TOML>", "-c", "hooks.Stop=<TOML>"]`, 모델 `--model <m>`, `resume_id`가 있으면 뒤에 `["resume", <id>]`.
    - TOML 값: `[{hooks=[{type="command",command="<JSON 문자열로 이스케이프한 명령>"}]}]` (프로토타입 `native_options`와 같음)
- 훅 해석:
  - `agent_id`가 있는 페이로드는 무시한다(하위 에이전트).
  - `hook_event_name` 매핑: `UserPromptSubmit`→Prompt(text=`prompt`), `Stop`→Stop(text=`last_assistant_message`), `Notification`→Approval(text=`message`).
  - `resume_id`는 `session_id` 필드에서 가져온다.
- 상태 계산(`fold`, 마지막 의미 있는 이벤트 기준):
  - Prompt → Working
  - Approval → Approval(대기 문구 = text)
  - Approval 뒤의 Input → Working
  - Stop → Done. 단 `viewed_ms`가 Stop 이후면 Idle
  - 이벤트가 없으면 Idle
  - Done이나 Idle 뒤의 Input은 상태를 바꾸지 않는다.
