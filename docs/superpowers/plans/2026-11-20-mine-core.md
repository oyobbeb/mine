# mine core (spike + phase 1: daemon and sessions) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Rust `mine` that can replace tmux inside Ghostty for a full day of use. Sessions must stay alive even when the daemon restarts.

**Architecture:** A single `mine` binary plays four roles:
- Client (TUI)
- Daemon (`mine daemon`)
- Per-session holder process (`mine hold`)
- Hook receiver (`mine _event`)

The holder process owns the PTY and keeps the last 2 MiB of output. The daemon attaches to each holder process, maintains an `alacritty_terminal` screen per session, and sends snapshots and live output to clients. Every connection is a JSON line protocol over a Unix socket.

**Tech Stack:** Rust 1.94 (edition 2024), tokio, ratatui 0.30 + crossterm 0.29 (output only), alacritty_terminal 0.26, portable-pty 0.9, clap 4, serde/serde_json, base64, sha2, libc, anyhow. tempfile for tests.

**Spec:** `docs/superpowers/specs/2026-11-20-mine-multiplexer-design.md` (design 5.1–5.3, 5.9, and phases 0–1 of 5.10)

## Scope

In this plan:
- Phase 0 spike
- Phase 1: daemon, holder process, claude/codex/shell sessions, project rail and state-grouped list, state detection via hooks, reattach, scrolling, selection copy, copy mode
- Replacing the Python prototype

Left out: usage limits and handoff (phase 2), reboot restore (phase 3), graph/files panes (phase 4), remote (phase 5), master session (phase 6), browser (phase 7), brew (phase 8), `⌃k` search. From phase 2 on, each phase gets its own plan that reflects the spike results.

## Global Constraints

- There is a single binary, `mine`. macOS (Apple Silicon) is the baseline, and it must also compile on Linux.
- The state directory is `~/.mine`, or the path in `MINE_STATE_DIR` if set. Newly created folders get permissions `0o700`.
- Unix socket paths must not exceed the macOS limit of 104 bytes. The holder socket lives at `<state>/run/<first 12 chars of sha256(id)>.sock`. Test state directories are created under a short path in `/tmp` (`tempfile::Builder::new().prefix("m").tempdir_in("/tmp")`).
- The prefix key is `⌃a` (0x01). Pressing `⌃a ⌃a` sends the 0x01 byte itself to the session.
- State symbols and list order are `◆ Needs approval → ◐ Working → ✓ Done → ○ Idle`. Exited sessions go in the Done group and are labeled `Exited`.
- Account chip colors: claude-a (A) `#e5c07b`, claude-b (B) `#c678dd`, codex (C) `#56b6c2`. Shell sessions have no chip.
- claude-a does not set `CLAUDE_CONFIG_DIR` (it uses `~/.claude` as is). claude-b uses `CLAUDE_CONFIG_DIR=<state>/profiles/claude-b`. mine never reads or stores credentials.
- The holder output buffer is 2 MiB (`RING_CAP = 2 * 1024 * 1024`) and scrollback is 10,000 lines (`SCROLLBACK = 10_000`).
- Protocol versions are client↔daemon `VERSION = 2` (bumped from 1 when Task 9 added the `Colors` message) and daemon↔holder `HOLD_VERSION = 1`. On a version mismatch, drop the connection and show an error.
- Do not add dependencies that are not in the Tech Stack above. If one is truly necessary, give the reason in the commit body.
- Commit rules:
  - The title is `type(scope): imperative English summary`. The body states what changed, why, and how it was verified, and the last line is `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - One task is one commit.
  - Before committing, `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` must pass. Until Task 12, `python3 -B -m unittest discover -s tests` must pass too.
- Version control uses GitButler (`but`) only. Code commits stack on the `feat/rust-core` branch.
  - First commit: `but commit --above docs/mine-design -b feat/rust-core -F - <ids>`
  - After that: `but commit -b feat/rust-core -F - <ids>`
  - For `<ids>`, pick only the file IDs from `but diff` that this task changed. Other agents may be working in the same repository, so do not include anyone else's changes.

## Review Focus

1. **Wide characters such as Hangul and emoji:** Wide characters in session output and session names must not shift the panes. → Task 4 `snapshot_rebuilds_same_screen`, Task 9 `term_render_handles_wide_chars`
2. **Output floods:** `cat`-ing a build log or a large file must not grow memory without bound, and other commands must stay responsive. → Task 3 `ring_keeps_last_bytes`, Task 6 `flood_output_keeps_ls_responsive`
3. **Window resize:** Resizing the Ghostty window or collapsing the list must give the session program the new size. → Task 3 `forwards_input_and_resize`
4. **0x01 inside a paste:** A `⌃a` byte inside pasted text must not be interpreted as a command. → Task 7 `prefix_inside_paste_passes_through`
5. **Leftover socket file:** If the daemon crashes and leaves only a `daemon.sock` file behind, the next run must still work. → Task 6 `stale_socket_is_replaced`

- [ ] **Step 3: Implement**

Built with std threads, no tokio. This is the full feature set, so it should almost never need upgrading.
1. Spawn the child with portable-pty `openpty(80x24)`.
2. Reader thread: put PTY output into the ring buffer, and send it as `Output` if a daemon is connected.

4. When the child exits, write the exit code to the exit file, send `Exited`, delete the socket file, and quit.

The snapshot is built in this order:
1. `\x1b[0m\x1b[H\x1b[2J`

4. Modes (1, 25, 1000/1002/1003, 1006, 2004)
5. Cursor position `\x1b[{row};{col}H`

### Task 5: Session launch command and hook state

**Files:**

**Interfaces:**
- Consumes: `paths::State`, `session::{Meta, Kind, SessionState}`
- Produces:
  ```rust
  // session.rs

  pub fn launch(meta: &Meta, state: &State, exe: &Path) -> Launch
  // hooks.rs

  pub fn parse_hook(payload: &serde_json::Value, now_ms: u64) -> Option<Event>

  ```
- Launch rules (every kind gets the `MINE_SESSION=<id>` environment variable and `cwd = meta.project`):
  - **Shell:** `[$SHELL or /bin/zsh, "-l"]`
  - **Claude:** `["claude", "--settings", <JSON>]`, plus `--model <m>` if there is a model and `--resume <id>` if there is a `resume_id`.
    - JSON: `{"hooks":{"UserPromptSubmit":[H],"Stop":[H],"Notification":[{"matcher":"permission_prompt","hooks":[C]}]}}`. Here `H = {"hooks":[C]}` and `C = {"type":"command","command":"<exe> _event <session_dir>"}`, and the command is quoted the `shlex` way.
    - Only claude-b gets `CLAUDE_CONFIG_DIR=<state>/profiles/claude-b`.
  - **Codex:** `["codex", "-c", "hooks.UserPromptSubmit=<TOML>", "-c", "hooks.Stop=<TOML>"]`, the model as `--model <m>`, and `["resume", <id>]` appended if there is a `resume_id`.
    - TOML value: `[{hooks=[{type="command",command="<command escaped as a JSON string>"}]}]` (same as the prototype's `native_options`)
- Hook parsing:
  - Ignore payloads that have `agent_id` (subagents).

**Files:**
- Create: `src/daemon.rs`, `src/conn.rs`, `tests/daemon.rs`

**Interfaces:**
- Consumes: everything Produced by Tasks 1–5
- Produces:
  - `daemon::run(state: State) -> anyhow::Result<()>` (tokio). Writes `daemon.pid` on startup.
  - `conn::Conn::connect_or_spawn(state: &State) -> anyhow::Result<Conn>`
    - If the socket connection fails, it removes the leftover `daemon.sock`, spawns `current_exe() daemon` with `pre_exec(setsid)` and output going to a log file, then retries the connection within 2 seconds.
    - It checks the `Hello` version.
  - `Conn::request(&mut self, msg: &ToDaemon) -> anyhow::Result<FromDaemon>` (synchronous, for headless use)
  - CLI:
    - `mine [--project DIR] new <name> [--kind claude|codex|shell] [--account claude-a|claude-b|codex] [--model M]`. The default kind is shell, and the project is `project_root(cwd)`.
    - `mine ls`: one line per session, `<symbol>\t<project folder name>\t<name>\t<account or ->\t<state word>\t<waiting text or ->`. The state word is `approval|working|done|idle|ended`, the symbols are ◆ ◐ ✓ ○, and exited sessions use ✓.
    - `mine [--project DIR] kill <name>`
- Daemon behavior:
  - **Startup:** Scan `sessions/*/meta.json` entries with `closed=false`. If the holder socket accepts a connection, the session is alive, and the daemon rebuilds its `Screen` from the Hello and the ring. If it cannot connect and there is an exit file, the session has exited. If it is a Shell, drop it from the list and save `closed=true`.
  - **New:** Validate the name (error if the same id exists). After `register`, save the meta, spawn the holder process with `pre_exec(setsid)`, then attach to it.
  - **Attach:** Make the client a subscriber of that session, forward `Resize` to the holder process, then send `Snapshot`. Save `viewed` as the current time (`<dir>/viewed`).
    - If the session is an exited Claude or Codex session and has a `resume_id`, relaunch it with `meta.resume_id` and then attach.
  - **Input:** Forward it to the holder process. If the state is Approval, record an `Input` event.
  - **Session size:** When several clients watch the same session, match the size of the client that last sent `Input` or `Resize`. The daemon remembers each client's last size (design 5.1).
  - **Poke:** Re-read the events. If any client is viewing that session, update `viewed`.
  - **Kill:** Send `Kill` to the holder process and save `closed=true`. Keep the folder and `events.jsonl`.
  - Send `Sessions` to all clients whenever the list changes.
  - Cap each client's send queue at 1024 messages. If it fills up, disconnect that client. On reattach it gets a snapshot.
  - Guard all state with a single `Arc<tokio::sync::Mutex<…>>`. Put the comment `// ponytail: global lock, per-session locks once there are hundreds of sessions` in the code.
